
 โครงสร้างโปรแกรม

- **GameClient.exe:** ใช้ Raylib สำหรับหน้าต่าง รับอินพุต และวาดเกมด้วยรูปทรงและข้อความ
- **GameServer.exe:** โปรเซสกติกาเกมที่ทำงานแยกจาก Client และส่งสถานะเกมผ่านเครือข่าย



 วิธีเล่น

1.  Open `GameServer.exe` 
2.  Open`GameClient.exe` = Player 1
3.  Open`GameClient.exe` = Player 2


 ปุ่มควบคุม

| ปุ่ม | การทำงาน |
| --- | --- |
| `W` `A` `S` `D` | เดิน |
| `E` | เก็บ Revive Kit เมื่ออยู่ใกล้ |
| Hold `E`  |  Revive player|
| คลิกซ้าย | Attack |

ผู้เล่นเริ่มต้นมี 100 HP การชุบสำเร็จทำให้กลับมา 40 HP และใช้ Revive Kit หนึ่งชิ้น

 โมเดลสถานะและการสื่อสาร

Server เป็นผู้ตัดสินสถานะเกมทั้งหมด ส่วน Client ส่งเฉพาะอินพุตและแสดง Snapshot ที่ได้รับกลับมา

- ผู้เล่นมีสถานะ `ALIVE`, `DOWNED` หรือ `DEAD` โดย HP หมดจะเปลี่ยนเป็น `DOWNED`
- ผู้เล่นที่ `DOWNED` จะเดิน โจมตี เก็บของ หรือเริ่มชุบไม่ได้ การชุบสำเร็จจะคืนเป็น `ALIVE` ที่ 40 HP
- Server เก็บตำแหน่ง HP สถานะการเชื่อมต่อ Revive Kit และความคืบหน้าการชุบของผู้เล่นทุกคน
- Client ส่ง `PlayerInputCommand` ผ่าน ENet พร้อมทิศทาง การกดปุ่ม เป้าหมายโจมตี และเลขลำดับคำสั่ง
- Server ตรวจเลขลำดับและกติกา แล้วส่ง `NetworkMatchSnapshot` กลับทุก tick ซึ่งมีข้อมูลผู้เล่น ไอเทม การชุบ และเหตุการณ์ล่าสุด
- การกำหนด Player ID ส่งแบบ reliable ส่วนอินพุตและ Snapshot เป็น UDP ที่อาจสูญหายได้ Snapshot ถัดไปจะส่งสถานะล่าสุด

 สมมติฐานและข้อจำกัด

- ผู้เล่นทุกคนใช้ไฟล์ Client/Server รุ่นเดียวกันและโครงสร้างแพ็กเก็ตตรงกัน
- ระบบยังไม่มีบัญชีผู้ใช้ การยืนยันตัวตน การบันทึกเกม หรือการเข้ารหัสข้อมูล
- หาก Server ปิดหรือการเชื่อมต่อหลุด Client ต้องปิดแล้วเปิดใหม่ เพราะยังไม่มีระบบ reconnect
- การป้องกันโกงยังไม่สมบูรณ์ เช่น ยังไม่มีการจำกัดระยะ/ความถี่การโจมตี และการตรวจค่าตัวเลขผิดปกติจาก Client

 เล่นผ่าน LAN

เครื่อง Host เปิด `GameServer.exe` และอนุญาต UDP port `27015` ใน Windows Firewall จากนั้นเครื่องผู้เล่นเปิด PowerShell ในโฟลเดอร์เกม แล้วรัน:

```powershell
.\GameClient.exe <Host-IP>
```

ตัวอย่าง: `.\GameClient.exe 192.168.1.10`
